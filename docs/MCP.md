# ربط Claude وOpenAI بالنظام (MCP)

يتيح النظام لـClaude وOpenAI إنشاء المهام وإسنادها إلى الموظفين وفتح المشاريع وإدارتها، عبر بروتوكول **MCP** (Model Context Protocol). يعمل الخادم على العنوان `https://<نطاقكم>/mcp` ويستخدم نقل **Streamable HTTP** بلا جلسات، ولا يحتاج إلى أي مكتبة إضافية.

## كيف يعمل الوصول

- يعمل النموذج بحساب خدمة واحد اسمه **المساعد الذكي** (`ai-assistant`) له الدور **AI Assistant**. كل ما يضيفه النموذج يظهر باسم هذا الحساب في المهام والمشاريع وسجل التدقيق (`mcp:<الأداة>`).
- لا يمكن تسجيل الدخول بهذا الحساب إلى الواجهة، فلا توجد له كلمة مرور صالحة.
- الصلاحيات الافتراضية: عرض المهام والمشاريع وإضافتها وتعديلها فقط. يغيّرها المدير من **الفريق والأدوار ← AI Assistant**، وتسري فوراً: الأداة غير المسموح بها تختفي من قائمة الأدوات، ويُرفض استدعاؤها برسالة واضحة.
- المصادقة برمز وصول (`Authorization: Bearer nxc_…`) ينشئه المدير من **الإعدادات ← المساعد الذكي (MCP)**. يُعرض الرمز **مرة واحدة** ولا يُخزَّن إلا مجزّأً (SHA-256)، ويمكن إلغاؤه في أي لحظة فيتوقف فوراً.
- الحد الأقصى 120 طلباً في الدقيقة لكل رمز.

## الإعداد لكل عميل

أنشئ رمزاً من صفحة الإعدادات، ثم استخدم الأوامر الجاهزة في البطاقة نفسها (تُملأ بالرمز تلقائياً):

| العميل | الإعداد |
|---|---|
| **Claude Code** | `claude mcp add --transport http nexus https://<نطاقكم>/mcp --header "Authorization: Bearer <الرمز>"` |
| **Claude Desktop** | ملف `claude_desktop_config.json` بالخادم `nexus` عبر `npx -y mcp-remote <العنوان> --header "Authorization: Bearer ${NEXUS_TOKEN}"` ومتغير البيئة `NEXUS_TOKEN` |
| **Anthropic API** | `mcp_servers: [{ type: "url", url: "<العنوان>", name: "nexus", authorization_token: "<الرمز>" }]` |
| **OpenAI (Responses API / Agents SDK)** | `tools: [{ type: "mcp", server_label: "nexus", server_url: "<العنوان>", authorization: "<الرمز>", require_approval: "never" }]` |

ملاحظة: تطبيقا claude.ai وChatGPT يشترطان OAuth للموصّلات المخصصة، وهذا غير مدعوم في هذه النسخة؛ المدعوم هو الاتصال برمز وصول كما في الجدول.

## الأدوات

| الأداة | الوظيفة | الصلاحية |
|---|---|---|
| `list_users` | الأشخاص الفعّالون الذين يمكن الإسناد إليهم | عرض المهام |
| `list_projects` | المشاريع مع حالتها ومواعيدها وعدد المهام المفتوحة | عرض المشاريع |
| `create_project` | فتح مشروع جديد (الاسم، الوصف، التواريخ، العميل، اللون) | إضافة مشروع |
| `add_project_member` | إضافة شخص إلى فريق مشروع | تعديل المشاريع |
| `list_tasks` | قائمة المهام مع مرشحات (المسؤول، المشروع، الحالة، نص، المتأخر) | عرض المهام |
| `get_task` | تفاصيل مهمة | عرض المهام |
| `create_task` | إنشاء مهمة، وإسنادها لشخص (يصله إشعار)، وربطها بمشروع | إضافة مهمة |
| `assign_task` | إسناد مهمة موجودة لشخص (يصله إشعار) | تعديل المهام |
| `update_task` | تغيير الحالة أو الأولوية أو الموعد أو العنوان أو الوصف | تعديل المهام |

- يمكن تحديد الشخص أو المشروع بالمعرّف أو بالاسم. إن طابق الاسم أكثر من سجل لا يخمّن الخادم، بل يعيد قائمة بالمرشحين ليختار النموذج.
- التواريخ بصيغة `YYYY-MM-DD`، والأولويات `low` أو `medium` أو `high`، والحالات `pending` أو `in_progress` أو `completed` أو `cancelled`.
- إكمال المهمة يسجّل تاريخ الإنجاز كما في الواجهة، وإعادة فتحها تمسحه.

## أمثلة تعليمات

- «أنشئ مشروع إطلاق المتجر وموعده 31 ديسمبر، وأضف إليه مهمة تصميم الصفحة الرئيسية لسارة بأولوية عالية قبل 10 نوفمبر.»
- «اعرض مهام عمر المتأخرة وأسند أقدمها إلى دينا.»
- «اجعل مهمة كتابة المحتوى منجزة.»

## الأمان

- استخدم HTTPS دائماً، وعامل الرمز كما تعامل كلمة المرور؛ لا تضعه في مستودع الشيفرة أو في رسائل.
- أنشئ رمزاً لكل عميل أو شخص بأسماء واضحة، وألغِ ما لم يعد مستخدماً. يظهر لكل رمز تاريخ آخر استخدام.
- ابدأ بأضيق الصلاحيات؛ الدور الافتراضي لا يصل إلى الفواتير أو المصروفات أو العملاء أو الحسابات.
- جدول الرموز `api_tokens` يُنشأ تلقائياً عند التشغيل (idempotent)، ولا يلزم ترحيل يدوي.
